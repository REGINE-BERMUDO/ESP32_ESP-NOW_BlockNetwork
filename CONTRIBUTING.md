# Adding your own results

Everyone contributes to the same class repository. Your changes should be
limited to your own top-level `lastname_firstname` folder.

## Prepare your folder

1. Use GitHub's **Fork** button to make your own copy of this repository,
   or use the shared repository directly if its owner has given you access.
2. Work from the latest repository files. Keep the common firmware and
   other students' folders unchanged.
3. Copy `docs/student-readme-template.md` to `lastname_firstname/README.md`,
   replacing the folder name with your own name.
4. Fill in your results from your own board during the approved block window.
5. Add `serial-monitor.png` and `serial-monitor-30s.mp4` inside your folder.
   A screenshot is not a replacement for the 30-second video.

Your local `OWNER_NAME` edit is for uploading to your board. Leave it out of
your contribution to the shared repository. If using Git, stage only your
results folder rather than every changed file.

## Send your contribution

If you worked in a fork, open a pull request targeting
`xavieryyyyyy/esp32_espnow_block_network`, branch `main`. Check the changed
files before sending: they should all belong to your own results folder.
Ask the repository owner to merge your pull request.

If you have direct write access, commit and push only your own folder.
Get the latest changes before pushing and preserve classmates' contributions.

Do not replace the shared sketch or edit someone else's results to resolve
a disagreement. Ask the owner to coordinate any common firmware change.

## Before submitting the link

Open the shared repository and check that your own folder, completed README,
screenshot, and video are present there. A fork or unmerged pull request alone
does not place your evidence in the shared repository.

Submit the shared URL, not your fork's URL:

https://github.com/xavieryyyyyy/esp32_espnow_block_network
